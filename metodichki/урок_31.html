Как писать код на Python в рамках ООП

Отдел: Классы. Неделя: 8. Возраст: 8–14.

Отдел: Классы. Неделя: 8. Возраст: 8–14.

🎯 Цель

Подготовить ребёнка к большому проекту «Тамагочи» следующим уроком. Собрать все кирпичики ООП вместе: конструктор с параметрами, атрибуты, методы с возвращением значения, наследование, цикл с объектами. Это репетиция.

Ученик может:

🕐 Поминутный план (60 мин)

  • 0–5. Разбор ДЗ к уроку 30. Демо: мини-РПГ с героем и врагом — оба классы, у героя — attack(), возвращающий урон.
  • 5–15. Теория. Методы с аргументами и возвратом: def attack(self, enemy): enemy.hp -= self.damage; return self.damage. Показываем, как один объект меняет другой объект.
  • 15–25. Совместный кодинг. Пишем РПГ:
class Character:
    def __init__(self, name, hp, damage):
        self.name = name
        self.hp = hp
        self.damage = damage
    def is_alive(self):
        return self.hp > 0
    def attack(self, other):
        other.hp -= self.damage
        print(f"{self.name} бьёт {other.name} на {self.damage}")

class Hero(Character):
    def heal(self):
        self.hp += 20
        print(f"{self.name} лечится, HP={self.hp}")

hero = Hero("Маг", 100, 15)
goblin = Character("Гоблин", 40, 5)
while hero.is_alive() and goblin.is_alive():
    hero.attack(goblin)
    if goblin.is_alive(): goblin.attack(hero)
  • 25–45. Самостоятельная задача. Ребёнок расширяет: класс Boss(Character) с усиленным уроном, список врагов, бой по очереди.
  • 45–55. Тестируем, ловим баги (бесконечный цикл при damage=0, отрицательный HP и т.п.). YandexGPT объясняет traceback.
  • 55–60. Итог. 3 пункта: методы возвращают и меняют; один объект взаимодействует с другим; ООП = карта для сложных программ. ДЗ — мини-банк.

💬 Ключевые фразы преподавателя

  1. «Сегодня мы собираем всё, что было, в один проект».
  2. «Один объект может менять другой — это мощь ООП».
  3. «return из метода работает точно как у обычной функции».
  4. «Проверяй состояние методом: is_alive(), is_hungry(), не копайся в атрибутах снаружи».
  5. «ООП = функции + данные в одной коробке».
  6. «Если метод меняет состояние — не забывай про self., а то изменится локальная переменная».
  7. «Список объектов в цикле — стандартный приём: for enemy in enemies:».
  8. «Один класс = одна сущность. Не пихай героя и карту в один».
  9. «Завтра будет Тамагочи — ты уже почти всё умеешь».
  10. «Имена методов — глаголы: attack, heal, feed, sleep. Атрибуты — существительные».

🎨 Мини-проект

Мини-РПГ, ~70 строк. Герой против 3 врагов подряд, счёт очков.

🏠 ДЗ (≤20 мин)

«Банк». Класс Account: имя, баланс. Методы deposit(amount), withdraw(amount) с проверкой, show(). Два счёта, перевод денег между ними (метод transfer(other, amount)).

✅ Критерии успеха

Ребёнок пишет класс с двумя методами (действие и проверка состояния), использует методы в цикле, различает self и параметры метода.

⚠️ Сложности и решения

  • Забывает self.hp внутри метода, пишет просто hp. Получает NameError.
  • Путает параметр метода и атрибут. Рисуем на бумаге.
  • Бой не заканчивается, потому что хп уходит в минус, а >= 0. Ставим > 0.
  • Не возвращает значение — думает, что print достаточно. Разбираем разницу.
  • «Слишком много кода». Делим на бумаге на 3 части: класс / создание / цикл.

🎁 Бонус

Добавить полиморфизм: Goblin.attack печатает «ржёт и бьёт», Boss.attack — «громит», у всех одинаковое имя метода, разное поведение.
