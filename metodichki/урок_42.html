Урок 42

Как работать с клавиатурой и анимациями в PyGame

Отдел: Разработки Неделя: 21 Возраст: 8-14

Отдел: Разработки Неделя: 21 Возраст: 8-14

🎯 Цель

Перейти от мыши к клавиатуре и ввести покадровую анимацию. Это подготовка к следующему проекту — платформеру, где персонаж бегает стрелками.

📚 Результаты

Ученик знает два способа ввода клавиатуры: on_key_down(key) (событие) и keyboard.left (состояние в update()). Понимает разницу: прыжок — событие, бег — состояние. Умеет реализовать покадровую анимацию через список картинок и счётчик: frames = ['run1', 'run2', 'run3']; actor.image = frames[tick // 5 % 3].

🛠️ Инструменты

GigaIDE, PyGame Zero, Kandinsky для генерации 3-4 кадров анимации бега персонажа (с одинаковой позой, но движением ног).

⚙️ Техтребования

Новый мини-проект в папке walker/. В images/: hero_idle.png, hero_run1.png, hero_run2.png, hero_run3.png, hero_jump.png. Промпт для Kandinsky: «пиксельный персонаж, мальчик, одна поза, прозрачный фон, 128×128».

🕐 Поминутный план (60 мин)

0-5: разбор ДЗ (звуки).

5-15: теория. Два режима клавиатуры. Живая демка: on_key_down — я прыгаю (один раз за нажатие), keyboard.left — я бегу, пока зажата. Рисую на доске.

15-25: совместный кодинг. Создаём простую сцену: земля, персонаж hero = Actor('hero_idle', (100, 500)). В update(): if keyboard.left: hero.x -= 3, if keyboard.right: hero.x += 3.

25-40: самостоятельно. Ребёнок добавляет прыжок: on_key_down(key): if key == keys.SPACE: hero.vy = -10. В update() — гравитация: hero.vy += 0.5; hero.y += hero.vy. Ограничение на землю: if hero.y > 500: hero.y = 500; hero.vy = 0.

40-55: анимация. Объясняю «флипбук»: сменяем картинки hero_run1/2/3 каждые 5 кадров при беге. Ввожу глобальный tick = 0, в update() tick += 1. Меняем image по формуле. Обсуждаем, почему деление и модуль.

55-60: итог. Персонаж бежит стрелками, прыгает пробелом, видна анимация ног.

💬 Ключевые фразы преподавателя

«Клавиатура — два лица: событие и состояние. Прыжок — одно нажатие, бег — зажатая кнопка». «on_key_down сработает один раз, даже если кнопку держишь 10 секунд». «keyboard.left — это прямо сейчас нажата или нет, проверяется 60 раз в секунду». «Анимация = смена картинок по кругу. Взрослые называют frame cycling». «tick // 5 — это „каждые 5 кадров меняем картинку“, иначе бег будет как в ускоренной перемотке». «Гравитация в играх — это просто +0.5 к vy каждый кадр, никакой магии». «Персонаж теперь живой — это огромный прогресс».

🎨 Мини-проект / этап сквозного проекта

Мини-проект «Человечек» — бегающий и прыгающий персонаж в пустой сцене. Это «заготовка» для будущего платформера на уроке 44.

🏠 ДЗ (≤20 мин)

  1. Добавить «разворот» героя: если бежит влево — картинка отражается (hero.flip = True если есть в вашей версии, иначе через 2 набора спрайтов). 2. Сделать так, чтобы в покое персонаж моргал — подменял hero_idle на hero_idle_blink каждые 2 секунды. 3. Отправить гифку.

✅ Критерии успеха

Герой двигается в обе стороны, прыгает по пробелу, анимация ног меняется при беге, не убегает за край экрана. Ребёнок различает «событие» и «состояние» словами.

⚠️ Сложности и решения

«Прыгает бесконечно» — забыт сброс vy = 0 на земле, либо не проверяем «на земле ли». «Анимация мерцает» — тик обновляется не на каждом кадре или формула tick % 3 без деления — кадры мелькают слишком быстро. «Бежит и всплывает» — случайно hero.y -= 3 вместо x.

🎁 Бонус

«Звёздная задача»: двойной прыжок — второй on_key_down(SPACE) в воздухе даёт ещё один импульс, но не более 2 раз. Логика через счётчик jumps_left.

🤖 Где подключаем ИИ

Kandinsky — генерация спрайтов анимации. Промпт-приём: «тот же персонаж, тот же стиль, та же поза, только нога поднята» — учимся добиваться консистентности. YandexGPT — объяснение кода гравитации, если ребёнок не понял формулу.
