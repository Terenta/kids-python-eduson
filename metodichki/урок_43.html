Урок 43

Как оптимизировать UX-игры

Отдел: Разработки Неделя: 22 Возраст: 8-14

Отдел: Разработки Неделя: 22 Возраст: 8-14

🎯 Цель

Научить делать так, чтобы в игру было ПРИЯТНО играть. Экран меню, кнопки, подсказки на экране, понятное состояние. Не про код — про заботу о игроке.

📚 Результаты

Ученик знает, что такое UX (user experience). Понимает принципы «игрок не должен гадать», «подсказка первые 3 секунды», «кнопка — это видимая зона с текстом и реакцией на наведение». Умеет нарисовать кнопку через Actor, проверить, попал ли клик в неё через actor.collidepoint(pos), сделать ховер (смена картинки при наведении мыши).

🛠️ Инструменты

GigaIDE, PyGame Zero, Kandinsky для кнопок и иконок, YandexGPT для текстов подсказок.

⚙️ Техтребования

Открываем игру «Поймай яблоко» с урока 40-41. Добавляем в images/: btn_play.png, btn_play_hover.png, btn_settings.png, icon_sound_on.png, icon_sound_off.png.

🕐 Поминутный план (60 мин)

0-5: разбор ДЗ (разворот и моргание).

5-15: теория. UX на примерах: показываю две игры — одну с меню и подсказками, другую без. Обсуждаем, в какую хочется играть и почему. Три правила: 1) всегда понятно, что делать; 2) каждое действие даёт фидбек; 3) можно выйти.

15-30: совместный кодинг. Превращаем текстовое меню «Нажми ПРОБЕЛ» в нарисованную кнопку. play_btn = Actor('btn_play', (400, 300)). В draw() для состояния menu — play_btn.draw(). В on_mouse_down(pos): if game_state == 'menu' and play_btn.collidepoint(pos): game_state = 'playing'.

30-45: самостоятельно. Ребёнок добавляет ховер: в on_mouse_move(pos) проверяем if play_btn.collidepoint(pos): play_btn.image = 'btn_play_hover' иначе обычная. Плюс подсказка первые 3 секунды игры: «Двигай мышкой, лови яблоки!» — исчезает через clock.schedule(hide_hint, 3.0).

45-55: кнопка «звук вкл/выкл» в углу. Переменная sound_on = True, клик по иконке — инвертирует, меняет картинку, выключает музыку через music.stop() / music.play('bg').

55-60: итог + ДЗ. Показываю разницу: до урока игра была сырая, сейчас — полированная.

💬 Ключевые фразы преподавателя

«UX — это забота об игроке. Игрок не умеет читать код». «Если игроку непонятно, что делать в первые 5 секунд — игра проиграна, он закроет». «Кнопка — это картинка, реагирующая на курсор». «Ховер — это маленький фидбек, говорящий „меня можно нажать“». «Подсказка — только вначале, потом мешает». «Звук вкл/выкл — обязательная кнопка в любой игре, иначе меня забанят родители». «UX-принцип: после каждого действия игрока — видимая реакция за 100 мс».

🎨 Мини-проект / этап сквозного проекта

Дополнение к проекту «Поймай яблоко»: красивое меню с кнопкой, ховер, подсказка, переключатель звука. Готовимся к полировке в финальном проекте.

🏠 ДЗ (≤20 мин)

  1. Добавить в меню вторую кнопку «Как играть?» — при клике показывает экран с 3 строчками правил. 2. Сделать хотя бы одну анимацию на hover — кнопка чуть увеличивается (через смену картинки). 3. Попросить родителя/друга поиграть 3 минуты и записать, что было непонятно.

✅ Критерии успеха

В игре есть минимум 2 кнопки, обе реагируют на ховер, есть подсказка для новичка, есть переключатель звука. Ребёнок на простом языке объясняет, почему UX важен.

⚠️ Сложности и решения

«Клик не попадает в кнопку» — проверяем collidepoint, координаты. «Ховер мигает» — забыли ветку else (когда курсор ушёл). «Подсказка не исчезает» — clock.schedule вызвали в draw(), где он срабатывает каждый кадр. Переносим в момент перехода в playing.

🎁 Бонус

«Звёздная задача»: плавное появление меню (fade-in) — через переменную alpha от 0 до 255, применяется через полупрозрачный прямоугольник в draw().

🤖 Где подключаем ИИ

YandexGPT — генерация текстов подсказок и правил. Промпт: «напиши 3 короткие строчки правил для игры „поймай яблоко“ для детей 7-10 лет». Kandinsky — кнопки в едином стиле с игрой.
