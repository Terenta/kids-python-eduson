Параметр vs Аргумент

Похожие слова — разный смысл

Параметр — имя в определении

def greet(name):
    #       ^^^^
    # name — это параметр
    # пустой ящик с именем "name"
    print(f"Привет, {name}!")

Параметр живёт внутри def — пустой ящик с именем.

Аргумент — значение при вызове

greet("Аня")
#      ^^^^^
# "Аня" — это аргумент
# письмо, которое кладём в ящик

Аргумент — конкретное значение при вызове.

Python кладёт аргумент "Аня" в параметр name — и внутри функции name == "Аня"

Как Python передаёт аргументы

Пошагово: что происходит при вызове greet("Аня")

  1. Встречает вызов greet("Аня") → находит функцию greet в памяти
  2. Входит в тело функции → создаёт локальную переменную name
  3. Присваивает: name = "Аня" — аргумент попадает в параметр
  4. Выполняет тело: print(f"Привет, {name}!") → выводит «Привет, Аня!»
  5. Выходит из функции → переменная name исчезает (она локальная)
  6. Возвращается к следующей строке после вызова → продолжает программу
Каждый вызов — новая «жизнь» параметра: создаётся → живёт → умирает

Область видимости (scope)

Параметр живёт только внутри своей функции

Python
def greet(name): # name видна ТОЛЬКО здесь print(f"Привет, {name}!") greet("Аня") # Попробуем обратиться к name снаружи: # print(name) # раскомментируй -> NameError! # У каждого вызова своя name: def double_greet(a, b): print(f"Привет, {a}!") print(f"Привет, {b}!") # a и b не пересекаются double_greet("Маша", "Саша") print("После функции: a и b больше не существуют")

Ключевой принцип: функция — изолированный «пузырь». Что внутри — снаружи не видно. Это защищает код от случайных конфликтов имён.

Именованные аргументы

Именованные аргументы делают вызов функции самодокументированным — читаешь и сразу понимаешь, что куда идёт

Когда использовать какой стиль?

Позиционные — коротко

# Хорошо: всего 2 параметра,
# смысл очевиден
draw_rectangle(10, 5)
greet("Аня")
print("Привет")

Идеально когда параметров мало и порядок интуитивен.

Именованные — явно

# Хорошо: много параметров,
# сразу понятно что есть что
create_hero(
    name="Аня",
    hp=100,
    attack=45,
    is_boss=False
)

Идеально когда параметров 3+, или они одного типа (несколько int/bool).

Правило Python: в вызове функции именованные аргументы всегда идут после позиционных. f(1, 2, key=val) ✓ / f(key=val, 1, 2) ✗

Прогрессия: line → triangle → diamond

Каждая следующая функция использует предыдущую

Python
def draw_line(width, sym="#"): print(sym * width) def draw_triangle(height, sym="*"): for i in range(1, height + 1): print(sym * i) def draw_diamond(size, sym="*"): # Верхняя половина for i in range(1, size + 1): print(" " * (size - i) + sym * (2 * i - 1)) # Нижняя половина for i in range(size - 1, 0, -1): print(" " * (size - i) + sym * (2 * i - 1)) draw_line(15) draw_triangle(5) print() draw_diamond(4)

Параметры по умолчанию

Если забыл передать — Python использует готовое значение

Python
# level=1 — значение по умолчанию def greet_hero(name, level=1, faction="Независимый"): print(f"Герой: {name}") print(f"Уровень: {level} | Фракция: {faction}") print("---") # Все параметры greet_hero("Зорро", 10, "EdisonGames") # Без faction — будет "Независимый" greet_hero("Аня", 5) # Только имя — level=1, faction="Независимый" greet_hero("Новичок")

Правило: параметры с default (level=1) всегда ПОСЛЕ обязательных (name). Иначе — SyntaxError.

Осторожно! Изменяемый default

Использовать список/словарь как default — опасная ловушка

Python
# ПЛОХО: список создаётся один раз! def add_score_bad(score, history=[]): history.append(score) return history print(add_score_bad(10)) # [10] print(add_score_bad(20)) # [10, 20] ??? print(add_score_bad(30)) # [10, 20, 30] ???! print("---") # ХОРОШО: используй None как default def add_score_good(score, history=None): if history is None: history = [] history.append(score) return history print(add_score_good(10)) # [10] print(add_score_good(20)) # [20] print(add_score_good(30)) # [30]

Правило: если нужен изменяемый default (list, dict, set) — используй None и создавай внутри функции.

Докстринги: документация функции

Тройные кавычки сразу после def — объясняют что делает функция

Python
def calc_score(hits, misses, bonus=0): """ Подсчитывает очки игрока. hits -- количество попаданий (10 очков каждое) misses -- количество промахов (-3 очка каждый) bonus -- бонусные очки (по умолчанию 0) """ score = hits * 10 - misses * 3 + bonus return score # Читаем документацию print(calc_score.__doc__) # Используем функцию result = calc_score(8, 3, 50) print(f"Итоговый счёт: {result}")

Стандарт EdisonGames: каждая публичная функция должна иметь докстринг. Это помогает команде понять код без лишних объяснений.

Аннотации типов (type hints)

Необязательно, но профессионально — IDE помогает, код читается как документация

Python
# Без аннотаций — что за name? str? int? def greet(name, level, active): pass # С аннотациями — всё ясно сразу def greet_typed(name: str, level: int = 1, active: bool = True) -> None: """Приветствует героя если он активен.""" if active: print(f"[Ур.{level}] Привет, {name}!") else: print(f"{name} сейчас недоступен") def calc_damage(base: int, multiplier: float = 1.0) -> int: """Вычисляет урон с множителем.""" return int(base * multiplier) greet_typed("Аня", 7) greet_typed("Боря", 3, active=False) print(f"Урон: {calc_damage(50, 1.5)}")
Аннотации не изменяют поведение Python — они для людей и инструментов, не для интерпретатора

Типичные ошибки с параметрами

Встретишь — не пугайся, читай сообщение об ошибке

Как читать traceback

Читай снизу вверх — там самое важное

Пример ошибки

Traceback (most recent call last):
  File "game.py", line 10, in <module>
    greet()
  File "game.py", line 2, in greet
    print(f"Привет, {name}!")
TypeError: greet() missing 1 required positional argument: 'name'

Расшифровка

  • Последняя строка — тип ошибки и её описание. Читай первой.
  • line 10 — здесь произошёл вызов, приведший к ошибке
  • line 2 — здесь ошибка внутри функции
  • missing 1 required positional argument → забыл передать name

Словарь урока 18

параметр
Имя-заполнитель в определении функции: def greet(name) — name это параметр. Как пустой ящик.
аргумент
Конкретное значение при вызове: greet("Аня") — "Аня" это аргумент. Письмо в ящик.
default
Значение по умолчанию: def f(x=10) — если x не передан, будет 10.
keyword arg
Именованный аргумент: greet(name="Аня") — передаём по имени, порядок не важен.
scope
Область видимости: параметр виден только внутри своей функции, снаружи — NameError.
docstring
Документация функции в тройных кавычках """...""" сразу после def. Читается через .__doc__.
type hint
Аннотация типа: def f(name: str) -> None. Не влияет на выполнение, помогает IDE и людям.

Самопроверка: термины

Назови термин по описанию — без подглядывания

Назови термин

  • «Значение, которое передаётся в функцию при вызове» → ?
  • «Имя-заполнитель в объявлении функции» → ?
  • «Значение, которое используется если аргумент не передан» → ?
  • «Передача аргумента по имени параметра» → ?

Ответы

  • аргумент
  • параметр
  • default (значение по умолчанию)
  • keyword argument (именованный аргумент)
