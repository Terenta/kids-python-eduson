Движение стрелками

keyboard.left и keyboard.right проверяем в update()

SPEED = 4  # скорость движения

def update():
    # Движение влево/вправо
    if keyboard.left:
        hero.x -= SPEED
    if keyboard.right:
        hero.x += SPEED

    # Ограничение — не выходить за края
    hero.x = max(40, min(WIDTH - 40, hero.x))

    # Гравитация (добавим позже)
    hero.vy += 0.5        # ускорение вниз
    hero.y += hero.vy     # применяем скорость

    # Земля — не проваливаться
    if hero.y >= GROUND:
        hero.y = GROUND
        hero.vy = 0       # скорость обнуляем
max(40, min(WIDTH-40, x)) — это «зажим в коридор». Взрослые разработчики называют это clamp. Гарантирует, что значение всегда в нужном диапазоне.

Прыжок и гравитация

Физика в играх — это просто +0.5 к скорости каждый кадр

GRAVITY = 0.5   # ускорение вниз каждый кадр
JUMP_POWER = -10  # начальная скорость прыжка (вверх)

def on_key_down(key):
    if key == keys.SPACE:
        # Прыгаем только если стоим на земле
        if hero.y >= GROUND:
            hero.vy = JUMP_POWER   # отталкиваемся вверх

def update():
    hero.vy += GRAVITY  # гравитация тянет вниз
    hero.y += hero.vy   # применяем скорость

    if hero.y >= GROUND:
        hero.y = GROUND
        hero.vy = 0     # приземлились

Гравитация в числах

Разбираем прыжок кадр за кадром

Как меняется vy за прыжок

Кадр | vy | y (от земли)
-----|-------|-------------
0 | -10.0 | 400 (земля)
1 | -9.5 | 390.5
2 | -9.0 | 381.5
...| ... | ...
20 | 0.0 | 300 (вершина)
...| ... | ...
40 | +10.0 | 390.5
41 | +10.5 | 400 (земля!)
Формула:
vy(кадр) = JUMP_POWER + GRAVITY × кадр

Вершина: кадр = |JUMP_POWER| / GRAVITY
= 10 / 0.5 = кадр 20

Настройка прыжка

  • Выше прыжок: уменьши JUMP_POWER (до -15)
  • Дольше в воздухе: уменьши GRAVITY (до 0.3)
  • Быстрое падение: увеличь GRAVITY (до 0.8)

Формула tick // 5 % 3 — разбор

Два оператора, одна строка, вечная анимация

Шаг 1: tick // 5

Целочисленное деление. Замедляет счётчик в 5 раз.

tick=0 → 0//5 = 0
tick=1 → 1//5 = 0
tick=4 → 4//5 = 0 (ещё тот же)
tick=5 → 5//5 = 1 (переключился!)
tick=9 → 9//5 = 1
tick=10 → 10//5 = 2 (следующий)

Шаг 2: ... % 3

Остаток от деления. Зацикливает на 3 кадрах.

0 % 3 = 0 (кадр 1)
1 % 3 = 1 (кадр 2)
2 % 3 = 2 (кадр 3)
3 % 3 = 0 (снова кадр 1!)
4 % 3 = 1 (снова кадр 2)
Итог: кадр меняется каждые 5 тиков и циклически перебирает 3 кадра.

Хочешь 4 кадра? Пиши % 4.
Хочешь медленнее? Пиши // 8.
Python
FRAME_SPEED = 5 NUM_FRAMES = 3 print(f"Скорость: каждые {FRAME_SPEED} тиков") print(f"Кадров: {NUM_FRAMES}") print() for tick in range(20): idx = (tick // FRAME_SPEED) % NUM_FRAMES bar = ['_'] * NUM_FRAMES bar[idx] = '#' print(f"tick={tick:2d} кадр={idx} {''.join(bar)}")

Полный код Walker

Всё вместе — ~40 строк, живой персонаж

WIDTH = 800
HEIGHT = 500
GROUND = 400
SPEED = 4
GRAVITY = 0.5
JUMP_POWER = -10
RUN_FRAMES = ['hero_run1', 'hero_run2', 'hero_run3']

hero = Actor('hero_idle')
hero.pos = (150, GROUND)
hero.vy = 0
tick = 0

def draw():
    screen.fill((135, 206, 235))  # небо
    screen.draw.filled_rect(
        Rect(0, GROUND+30, WIDTH, HEIGHT), (101, 67, 33))  # земля
    hero.draw()

def update():
    global tick
    tick += 1
    moving = False

    if keyboard.left:
        hero.x -= SPEED
        moving = True
    if keyboard.right:
        hero.x += SPEED
        moving = True

    hero.x = max(40, min(WIDTH-40, hero.x))
    hero.vy += GRAVITY
    hero.y += hero.vy

    if hero.y >= GROUND:
        hero.y = GROUND
        hero.vy = 0

    if moving and hero.y >= GROUND:
        hero.image = RUN_FRAMES[(tick // 5) % 3]
    elif hero.y < GROUND:
        hero.image = 'hero_jump'
    else:
        hero.image = 'hero_idle'

def on_key_down(key):
    if key == keys.SPACE and hero.y >= GROUND:
        hero.vy = JUMP_POWER

Разбираем код по секциям

Из чего состоит Walker — 6 блоков

  1. Константы — WIDTH, HEIGHT, GROUND, SPEED, GRAVITY, JUMP_POWER. Всё настраивается в одном месте, не надо искать магические числа по коду.
  2. Создание персонажа — Actor('hero_idle'). Добавляем наши атрибуты: hero.vy = 0, tick = 0.
  3. draw() — рисуем небо, землю, персонажа. Выполняется 60 раз/сек, только рисование, никакой логики.
  4. update() — движение — проверяем keyboard, двигаем hero.x, применяем clamp.
  5. update() — физика — vy += GRAVITY, y += vy, проверка приземления.
  6. update() — анимация — выбор кадра в зависимости от состояния (бежит, прыгает, стоит).

Типичные ошибки

Три бага, которые встречаются у всех — и как их чинить

Прыгает бесконечно

Забыта проверка «на земле ли». Персонаж прыгает в воздухе снова и снова.

# Неправильно:
if key == keys.SPACE:
    hero.vy = JUMP_POWER

# Правильно:
if key == keys.SPACE:
    if hero.y >= GROUND:
        hero.vy = JUMP_POWER

Анимация мерцает

Формула без деления — кадры меняются слишком быстро.

# Мерцает (60 смен/сек):
frame = tick % 3

# Плавно (12 смен/сек):
frame = (tick // 5) % 3

Улетает за экран

Забыт clamp — ограничение координаты.

# Правильно — clamp:
hero.x = max(
    40,
    min(WIDTH-40, hero.x)
)

Game Feel — профессиональные техники

Почему Mario ощущается лучше, чем случайный платформер

Coyote Time

Разрешить прыжок ещё 5-8 кадров после выхода с платформы. Игрок чувствует себя умным, а не обманутым.

coyote = 6  # кадров

def update():
    global coyote
    on_ground = hero.y >= GROUND
    if on_ground:
        coyote = 6
    else:
        coyote -= 1

def on_key_down(key):
    if key == keys.SPACE:
        if coyote > 0:  # не только на земле
            hero.vy = JUMP_POWER
            coyote = 0

Jump Buffering

Запомнить нажатие прыжка на несколько кадров вперёд. Если игрок нажал чуть раньше приземления — прыжок всё равно сработает.

jump_buffer = 0  # кадров

def on_key_down(key):
    global jump_buffer
    if key == keys.SPACE:
        jump_buffer = 8  # запомнить на 8 кадров

def update():
    global jump_buffer
    if jump_buffer > 0:
        jump_buffer -= 1
        if hero.y >= GROUND:
            hero.vy = JUMP_POWER
            jump_buffer = 0
