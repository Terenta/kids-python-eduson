Что такое MVP?

Minimum Viable Product — минимально работающая версия

❌ Плохой план

  • Игра с 5 уровнями
  • Босс в конце каждого
  • Система прокачки
  • Магазин предметов
  • Мультиплеер
  • Кастомизация персонажа

→ Не успеешь за 3 урока. Ничего не будет готово.

✅ MVP план

  • Одна сцена, один герой
  • Одна базовая механика
  • Счёт или прогресс
  • Конец игры + рестарт
  • Пара спрайтов
  • Один звук

→ Готово через 3 урока. Можно показывать!

Выбираем жанр: 5 вопросов

Ответь честно — и жанр выберется сам

  1. Что тебе интереснее: экшен с движением или загадки и вопросы?
  2. Ты уже делал коллизии (когда объекты сталкиваются)? Если нет — выбирай ловилку, не платформер.
  3. Сколько спрайтов тебе нужно нарисовать? Меньше 5 — быстрее запустить.
  4. Есть ли чёткий конец у твоей игры? Game over или победа — обязательно.
  5. Объяснишь механику в одном предложении? Если нет — идея слишком сложная.

Игровой цикл — Game Loop

Основа любой игры — цикл, который крутится 60 раз в секунду

Как мультфильм: 24 кадра в секунду = плавное движение. Игра = 60 кадров в секунду.
  • draw() — рисует текущий кадр (очищает экран и рисует всё заново)
  • update() — двигает объекты, проверяет коллизии, меняет состояние
  • on_key_down(key) — реагирует на нажатия клавиш
  • on_mouse_move(pos) — реагирует на мышь
Python
import time frame = 0 fps = 60 duration = 0.2 # симулируем 0.2 сек print("Симуляция Game Loop:\n") start = time.time() while time.time() - start < duration: frame += 1 print(f"Кадров за {duration}с: ~{frame}") print(f"Расчётный FPS: ~{int(frame/duration)}") print() print("В реальной игре:") print(" draw() → рисуем экран") print(" update() → двигаем объекты") print(" Всё это 60 раз в секунду!")

Машина состояний

Игра всегда находится в одном из состояний — и знает, что делать в каждом

Состояния типичной игры:

'menu' → нажал ПРОБЕЛ → 'playing'
'playing' → 0 жизней → 'gameover'
'playing' → нажал P → 'paused'
'gameover' → нажал R → 'menu'
game_state = 'menu'
Одна переменная управляет всей игрой.
Python
game_state = 'menu' score = 0 lives = 3 def handle_action(action): global game_state, score, lives if game_state == 'menu' and action == 'space': game_state = 'playing' print("Игра началась!") elif game_state == 'playing' and action == 'hit': lives -= 1 print(f"Попадание! Жизней: {lives}") if lives == 0: game_state = 'gameover' print("Game Over!") elif game_state == 'gameover' and action == 'restart': game_state = 'menu' lives = 3 score = 0 print("Возврат в меню.") actions = ['space', 'hit', 'hit', 'hit', 'restart', 'space'] for a in actions: print(f"\nДействие: {a} | Состояние: {game_state}") handle_action(a)

Разбираем скелет

Каждая часть скелета — зачем она нужна?

  1. WIDTH = 800, HEIGHT = 500 — размер окна. Меняй под свою игру. Стандарт: 800×600.
  2. game_state = 'menu' — машина состояний. Начинаем с меню, не с игры. Без этого игра сразу начнётся без подготовки.
  3. cat = Actor('cat_idle') — создаём персонажа. Файл cat_idle.png должен лежать в папке images/.
  4. def draw() — вызывается 60 раз в секунду. Рисует текущий кадр. Не считай здесь логику!
  5. def update() — вся логика движения и коллизий. Пока пустая — добавим на уроке 46.
  6. def on_key_down(key) — реагирует на нажатия. keys.SPACE, keys.LEFT, keys.RIGHT — стандартные константы PyGame Zero.

Типичные ошибки при старте

❌ Логика в draw()

score = 0 def draw_bad(): global score score += 1 # ОШИБКА! 60 раз/сек! print(f"Счёт: {score}") for _ in range(5): draw_bad() print("За 1 секунду счёт вырастет до 60!")

✓ Логика в update()

Python
score = 0 timer = 0 def update(dt=1/60): global score, timer timer += dt if timer >= 1.0: # раз в секунду score += 1 timer = 0 for _ in range(120): # 2 секунды update() print(f"За 2 секунды счёт: {score}") print("Правильно — счёт растёт по 1 в секунду")
