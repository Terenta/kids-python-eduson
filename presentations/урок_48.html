Структура 5-минутной речи

Идеальная защита состоит из 5 блоков — по минуте каждый

1
Идея — зачем эта игра? Что вдохновило? (~1 мин)
2
Демо — показываем игру вживую, поясняем что происходит (~1.5 мин)
3
Сложность — что было трудно? Как решил? (~1 мин)
4
Гордость — что получилось лучше всего? Какой код нравится? (~0.5 мин)
5
Планы — что добавил бы если было время? Что изучишь дальше? (~0.5 мин)

Как отвечать на вопросы

Вопросы — не ловушка, а интерес к твоей работе. Отвечай честно и по существу

Типичные вопросы:

  • «Почему выбрал эту игру?» — расскажи идею
  • «Что было сложнее всего?» — один конкретный баг
  • «Что бы добавил?» — из своего ideas-листа
  • «Сколько времени занял проект?» — примерно часов

Пришло время задавать вопросы

Что хочешь спросить — про карьеру, про следующий курс, про то что непонятно?

Финальная самопроверка

  1. Чем отличается функция от метода класса?
  2. Что такое Game Loop и State Machine? Где ты их использовал?
  3. Как сохранить данные между запусками программы? Назови два способа.
  4. Что такое рефакторинг и зачем его делают?
  5. Если бы у тебя было ещё 10 уроков — что бы добавил в свою игру?

Ориентиры для ответов:

  1. Метод — функция внутри класса, имеет доступ к self (к данным объекта).
  2. Game Loop — бесконечный цикл обновления игры. State Machine — явные состояния (MENU/PLAY/OVER).
  3. В файл (txt/json через open/json.dump) или в базу данных (sqlite3).
  4. Улучшение структуры кода без изменения поведения — читаемость, DRY, SRP.
  5. Открытый ответ — любые идеи приветствуются!

Частые ошибки в финальных проектах

Разбираем и исправляем — это делают все разработчики

❌ Бесконечный цикл без выхода:

running = True score = 0 while running: score += 1 # Нет условия выхода! # Программа зависнет навсегда print("Игра окончена") # Никогда не выполнится

✓ Правильно — с условием выхода:

running = True score = 0 lives = 3 while running and lives > 0: score += 1 if score >= 10: running = False # Выход по победе print(f"Игра окончена! Счёт: {score}")

❌ Глобальные переменные везде:

score = 0 # Глобальная — плохо! def add_points(n): global score score += n # Опасно в большом проекте add_points(5) print(score)

✓ Возвращаем значение — чище:

def add_points(current_score, n): return current_score + n # Чисто! score = 0 score = add_points(score, 5) print(f"Счёт: {score}")

Финальная неделя — 5 задач для самостоятельного роста

  1. Рефакторинг финального проекта
    Найди 3 места где код можно сделать чище или короче. Примени DRY-принцип. Задокументируй изменения в README.md.
  2. Добавь систему сохранения хай-скора
    Используй json.dump и json.load чтобы лучший результат сохранялся между запусками игры.
  3. Создай README.md для проекта
    Напиши: название, описание, как запустить, технологии, что планируешь добавить. Это твоё первое портфолио-описание.
  4. Придумай и напиши три фичи
    В файл ideas.md — описание трёх улучшений с оценкой сложности: Лёгко / Средне / Сложно. Прими это как backlog.
  5. Поделись игрой с другом или семьёй
    Попроси кого-то сыграть и запиши их реакцию. Что было непонятно? Что понравилось? Это настоящее UX-тестирование.
